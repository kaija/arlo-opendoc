Failure modes

Three things account for almost every page on this service. Work them in order — the cheap checks first.

Gateway timeout at the edge

The gateway gives up on the charge worker after 8 seconds. If the dashboard shows 504s but the worker's own error rate is flat, the worker is alive and slow rather than broken. Confirm with the worker's recent logs before touching anything:

kubectl logs -n payments deploy/charge-worker --since=15m

Charge worker backlog

A backlog over 2,000 messages means the worker cannot keep up with the queue. Scale to six replicas first and only then look for the cause.

Downstream ledger timeout

The ledger holds a row lock per merchant. When it stalls, charges are accepted but never settle, so the customer sees a pending authorisation and we see nothing at all.

## Failure modes
 
Three things account for almost every page on this service.
 
### Gateway timeout at the edge
 
The gateway gives up on the charge worker after **8 seconds**.
 
```
kubectl logs -n payments deploy/charge-worker --since=15m
```
 
### Duplicate charge on client retry
 
A client that retries a charge after a gateway timeout without an
idempotency key creates a second authorisation. The worker cannot tell the two apart, so the ledger records both.
 
[ADR-014: Idempotency strategy](/architecture/adr-014)
